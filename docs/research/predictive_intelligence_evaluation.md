# Predictive intelligence evaluation

The historical V1.4.1–1.4.3 comparisons and their cohort restrictions remain in the earlier research reports. In the V1.4.3 independent 30-pair holdout, L1 LightGBM had lower pair-level WAPE than TSB but substantially worse signed bias and sampled-total WAPE. There was no basis for promoting a new production candidate.

The deployable statistical strategies are fixed TSB α=β=0.1, the last-28-day mean, and seven-day seasonal naive. Each uses up to 90 actual historical observations for the selected pair. These strategies are explicitly experimental in the API and frontend. The existing registered hybrid remains the default.

Pair-level interval calibration uses historical rolling-origin absolute errors from the same method and pair. For each lead, the 80% or 95% interval uses the finite-sample rank ceil((n+1)×coverage), clipped below at zero. At least 20 calibration origins and a valid rank are required. A 90-day history supports 35 origins at a 28-day horizon. Calibration windows overlap and the distribution can change, so these are empirical intervals with no promised time-series coverage. There is no segment-specific or pooled fallback. Intervals are not produced for aggregate batch totals.

A deterministic synthetic check used 90 calibration days and 28 later evaluation days from a seeded Poisson series. The 80% interval achieved 64.29% empirical coverage, mean width 3.62 and interval score 5.11. The 95% interval achieved 100% empirical coverage, mean width 6.76 and interval score 6.76. Both had 35 rolling calibration origins. These are small controlled examples, not estimates of real-world reliability. Undercoverage at 80% is material and needs further investigation.

The anomaly smoke evaluation injected three spikes into a constant synthetic demand series. Three flags matched all three injected dates, giving precision, recall and F1 of 1.0 on that constructed example. It does not validate performance on real anomalies, demand drops or prolonged zero runs. Demand signals use only the preceding 28 observed days. A nonzero MAD uses the modified z-score; the zero-MAD case uses explicit absolute/proportional rules. Prolonged zero flags require 14 zeros after a positive observation and sufficient prior nonzero frequency. These are alerts for review, not stockout or fraud labels. Weekly price-risk flags use observed quote changes of at least 30%, with at least 60% classified high.

One bounded live PostgreSQL check ran TSB forecasting for three pairs with seven-day horizons. Chunk size 1 had 0.115 seconds inference and 9.968 seconds end-to-end; chunk size 3 had 0.047 seconds inference and 2.104 seconds end-to-end. These one-shot timings include different warm-cache states and are not a scalability benchmark. Both saved snapshots were retrieved successfully. A pair demand-risk request returned HTTP 200 in 0.432 seconds and a TSB interval request returned HTTP 200 in 1.650 seconds. A separate pair price-risk request returned HTTP 200 in 2.111 seconds and zero signals. TestClient exercised the current code against the live database; these were not browser tests.

The research comparison charts are [V1.4.2 ablations](figures/v1_4_2_ablation_comparison.png) and [V1.4.3 holdout comparison](figures/v1_4_3_holdout_comparison.png). Both are small derived visualizations and omit source sales records. Raw local artifacts remain under ignored research output directories.

Further validation should compare coverage by horizon and intermittent segment on genuinely new chronological data, examine interval width and coverage under regime change, and evaluate anomaly signals with verified labels. Synthetic signals cannot establish alert precision in real stores. The statistical references for residual intervals and robust outlier scoring are [MAPIE residual scores](https://github.com/scikit-learn-contrib/MAPIE/blob/master/doc/content/conformal-prediction/conformity-scores.md) and the [NIST report on modified z-scores](https://tsapps.nist.gov/publication/get_pdf.cfm?pub_id=957454).

A temporary local FastAPI instance loaded the updated code for HTTP checks. `/health`, `/forecast/methods` and `/risk/demand?product_id=4&store_id=1` returned HTTP 200 in 0.636, 0.076 and 0.657 seconds respectively. The temporary instance was stopped after the checks.

## Remaining phase work

The current release is a bounded foundation for predictive intelligence. Pair intervals have not been validated on independent real-world data and the controlled 80% example undercovered. Segment-level calibration and aggregate interval calibration remain open. Run storage is local JSON with synchronous execution and existing pair limits; PostgreSQL persistence, resumable jobs and broad-scope asynchronous workloads are not implemented. A failed run records progress but does not preserve partial chunk forecasts.

The risk API covers pair-level demand, daily store-total deviations and weekly price signals. The store route reuses daily historical totals and rejects missing-date series. Forecast-residual anomalies, Isolation Forest comparisons and real labeled anomaly evaluation remain open. A single in-process TestClient request against live PostgreSQL for store 1 returned HTTP 200 with six signals in 21.197 seconds. This is close to the database timeout and needs performance work. The risk scores are fixed rules without demonstrated operational calibration. The React interface has automated checks but no new browser walkthrough was performed for these additions. Complete this validation and operational work before treating the phase as ready for prescriptive decisions.
